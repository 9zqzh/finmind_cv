## 一、系统定位

**学院教学小助手**是面向广东金融学院本科生的一站式 AI 智能体，目标是成为"学生口袋里的 AI 辅导员"：用自然语言对话作为核心入口，把原本散落在教务系统、学院网站、微信群、纸质手册中的信息聚合到一个网页里。

### 当前阶段：阶段 1（火山杯）

完整产品规划包含 M1-M12 共 12 个模块（见第五节对照表），但当前只实现**阶段 1 的最小闭环**：

|---|---|---|
| 1 | 课表查询 tool + 接口 | ✅ 已实现 |
| 2 | 教室课表 tool + 接口 | ✅ 已实现（含空闲教室查询） |
| 3 | 成绩查询 tool + 接口 | ✅ 已实现（含单科明细） |
| 4 | 培养方案 tool + 接口 | ✅ 已实现 |
| 5 | 知识库 RAG | ✅ 基础版已实现（关键词检索，**资料为示例数据，待替换**） |
| 6 | 学院网站信息查询 | ✅ 已实现（通过 gduf-web-api 实时搜索学院官网公开内容） |

一句话验收标准（引自技术选型文档）：

> 用户打开浏览器，完成一次真实教务登录，用自然语言询问课表或成绩，系统调用真实工具返回结构化结果；用户还可以询问学院制度或竞赛信息，系统从知识库/资讯数据中检索并给出带来源的回答；用户也可以搜索学院官网的实时公开内容（新闻、通知、师资等）。支持多轮对话记忆与流式输出。

## 三、功能模块详解

### 模块 1：AI 自然语言对话

- **核心能力**：用户用大白话提问，Agent（DeepSeek + PydanticAI）自动识别意图，从 14 个工具中选择合适的工具取真实数据，再用自然语言组织回答；结果附带 `result_type`，前端据此渲染表格卡片而不只是纯文本。支持多轮对话记忆（滑动窗口最近 6 轮）与 SSE 流式输出（思考过程、工具调用、文本增量逐步推送）。
- **典型场景**：
  - "我今天有什么课？" → 调用课表工具 → 文本回答 + 课表卡片
  - "博学楼周三上午有哪些课" → 调用教室课表工具 → 教室占用表格
  - "帮我看看哪个教室空着" → 调用空闲教室工具 → 空闲教室名单
  - "学院最近有什么通知" → 调用官网搜索工具 → 模型总结提炼官网实时内容
  - "最近有什么竞赛可以参加" → 调用竞赛列表工具 → 模型逐场介绍比赛与报名状态并附链接
  - "缓考应该怎么申请？" → 调用知识库检索 → 回答附来源文件名
  - "帮我找几篇关于深度学习的论文" → 调用学术资源搜索工具 → 模型逐篇介绍论文并附上链接与 PDF 下载地址
  - 未登录时问课表 → 模型按提示词约束提示“请先登录”，**不会编造数据**
- **交互流程**：输入问题（或点快捷问题按钮）→ 等待 Agent 执行（含工具调用）→ 展示文本回答 + 结构化卡片 + 来源标签。
- **实现状态**：✅ 已实现。知识问答不依赖登录即可使用；涉及个人教务数据的提问需要先登录。

### 模块 2：验证码登录与会话管理

- **核心能力**：对接教务系统真实登录——获取验证码图片（base64）、提交学号/密码/验证码、查询登录状态、退出登录。后端为每个用户维护独立会话（独立 Cookie），空闲 120 分钟（可配置）自动过期。
- **典型场景**：新生第一次打开网站 → 被引导到登录页 → 刷新验证码直到看清 → 登录成功进入主页。
- **交互流程**：
  1. 前端调 `/api/auth/captcha`：后端创建会话并返回验证码图 + `session_token`；
  2. 用户填写学号/密码/验证码，前端调 `/api/auth/login`；
  3. 成功后 token 存入 `sessionStorage`，后续所有请求自动携带 `X-Session-Token` 请求头；
  4. 页面刷新时前端用 `/api/auth/status` 向后端确认登录是否仍有效。
- **实现状态**：✅ 已实现。验证码错误（`AUTH_CAPTCHA_INVALID`）、账号密码错误（`AUTH_FAILED`）、会话过期（`SESSION_EXPIRED`）均有明确错误码与前端提示。**注意：登录依赖教务系统可用性，需真实学号验证（联调待办）**。

### 模块 3：个人课表查询

- **核心能力**：查询本人指定学期（格式 `YYYY-YYYY-1`）的课表，可按教学周（1-30）过滤；返回课程名、教师、教室、星期、节次、周次（含单双周解析）。
- **典型场景**："这周五有什么课""我第 3 周的课表"。
- **交互流程**：聊天提问（模型自动从问题里提取学期/周次，必要时追问）或课表页手动填学期查询 → 表格展示。
- **实现状态**：✅ 已实现（`query_schedule` 工具 + `GET /api/schedule` + 前端页面）。

### 模块 4：教室课表查询

- **核心能力**：查询某学期某校区/教学楼内所有教室的占用情况（哪间教室、星期几、第几节、上什么课、哪个班），可用于找空教室自习。另有专门的空闲教室查询工具（`query_empty_classrooms`），直接返回空闲教室名单。
- **典型场景**："博学楼周三上午有哪些课""帮我看看哪个教室空着"。
- **交互流程**：页面填学期（校区/教学楼可留空查全部）→ 表格展示；也可在对话中提问。教学楼代码通过 `get_buildings` 动态获取，不硬编码。
- **实现状态**：✅ 已实现（`query_classroom_schedule` 工具 + `GET /api/classroom-schedule` + `GET /api/classroom-buildings` + 前端页面）。

### 模块 5：空闲教室查询

- **核心能力**：在教室课表数据基础上过滤出空闲教室，按学期、校区、教学楼、周次查询哪些教室在指定时段没有课，直接返回空闲教室名单供学生自习参考。
- **典型场景**："帮我看看博学楼周三上午有哪些空教室""下周清远校区有什么教室可以用"。
- **交互流程**：聊天提问 → 模型调用 `query_empty_classrooms` 工具 → 模型用自然语言汇总空闲教室名单。
- **实现状态**：✅ 已实现（`query_empty_classrooms` 工具，复用教室课表数据过滤）。结果属于纯文本降级类型，前端只展示模型总结的文字。

### 模块 6：成绩查询

- **核心能力**：查询本人全部成绩，支持按学期过滤；返回每门课的成绩、学分、学时、绩点、考核方式、课程属性，以及总需/已修/剩余学分和主修/辅修平均绩点统计。
- **典型场景**："我这学期的成绩怎么样""我大二的绩点是多少"。
- **交互流程**：聊天提问或成绩页查询 → 统计摘要 + 成绩表格卡片。
- **实现状态**：✅ 已实现（`query_grades` 工具 + `GET /api/grades` + 前端页面）。
- **待开发**：绩点趋势图表、薄弱科目分析、排名参考（需求文档 M3 的进阶项）。

### 模块 7：单科成绩明细

- **核心能力**：查询某一门课的总成绩构成——平时/期中/期末各自分数与占比。
- **典型场景**："我高数期末占多少分""大学英语的平时成绩是多少"。
- **交互流程**：必须先查过成绩列表（jwxtapi 的约束），模型拿到科目 `index` 后追问查询；HTTP 方式为 `GET /api/grades/{index}/detail`。无明细的成绩会明确提示。
- **实现状态**：✅ 已实现（`query_grade_detail` 工具 + 接口；会话内缓存成绩列表解决 index 映射）。

### 模块 8：培养方案查询

- **核心能力**：查询本专业培养方案的全部课程清单（开课学期、课程代码、开课单位、学分、学时、考核方式、课程属性、是否考试）。
- **典型场景**："我们专业培养方案要修多少学分""大二上学期有哪些必修课"。
- **交互流程**：聊天提问或培养方案页一键查询 → 课程表格（分页展示）。
- **实现状态**：✅ 已实现（`query_training_plan` 工具 + `GET /api/training-plan` + 前端页面）。

### 模块 9：知识库检索（制度流程问答）

- **核心能力**：把学生手册、规章制度、办事流程整理成 Markdown 文件放入 `data/knowledge/`，系统启动时自动切片建索引；用户提问时按关键词检索最相关片段，由模型基于片段作答并**强制附带来源**。检索不到时如实回答"没有找到依据"，不编造。
- **典型场景**："缓考怎么申请""补办学生证要什么材料"。
- **交互流程**：聊天提问 → 检索 top-3 片段 → 模型作答 + 来源标签；或在知识与资讯页直接搜索看原文片段。
- **实现状态**：✅ 检索链路已实现；⚠️ **目录中的资料为示例数据，待替换**为真实学院制度文件；检索方案当前为关键词评分（零依赖），升级到向量检索（ChromaDB）为规划项。

### 模块 10：学院资讯与竞赛信息查询

- **核心能力**：学院网站资讯（通知、讲座、新闻）与竞赛平台信息的统一检索入口。当前以静态 JSON/Markdown 文件承载（`data/information/`），检索方式与知识库相同。
- **典型场景**：“最近有什么竞赛可以参加”“学院最近有什么通知”。
- **交互流程**：与知识库相同，前端有独立的资讯搜索页面。
- **实现状态**：✅ 检索链路已实现；⚠️ **静态数据为示例，待替换**。另：学院竞赛管理与问答平台（aijspt）的实时信息已通过 `gduf-web-api` v0.2.1 接入并注册为 Agent 工具：`query_competitions`（比赛列表，支持年份/状态/分类/学院/关键词筛选）、`query_competition_detail`（单场比赛详情：时间线、赛道、报名要求、附件）、`query_competition_notices`（平台通知公告）与 `query_competition_clubs`（竞赛社团列表）。结果属于纯文本降级类型，前端只展示模型总结的文字。

### 模块 11：学院官网公开信息搜索

- **核心能力**：通过 `gduf-web-api` 实时搜索学院官网（https://ai.gduf.edu.cn/）的公开内容，包括学院新闻、通知公告、学生活动、师资队伍、专业介绍等。搜索结果由模型总结提炼后以自然语言回答，不展示原始结构化数据。
- **典型场景**："学院最近有什么通知""某位老师是谁""学院有哪些专业"。
- **交互流程**：聊天提问 → 模型判断适用 `search_website` 工具 → 按关键词搜索官网 → 模型基于返回结果总结提炼回答。
- **实现状态**：✅ 已实现（`search_website` 工具 + `gduf-web-api` 客户端 + 官网适配层）。结果属于纯文本降级类型，前端只展示模型总结的文字，不渲染原始条目 JSON。

### 模块 12：学术资源搜索

- **核心能力**：通过 `gduf-academic-api` 搜索 arXiv、Semantic Scholar 等开放学术平台的论文与文献资料，返回标题、作者、年份、摘要、论文页面链接与 PDF 下载地址。支持通过 `ACADEMIC_PROXY` 环境变量配置代理以解决境外平台访问不稳定的问题。
- **典型场景**：“有没有关于深度学习的论文”“帮我找几篇强化学习的文献”“推荐一些学术资源”。
- **交互流程**：聊天提问 → 模型将中文主题翻译为英文关键词后调用 `search_academic` 工具 → 搜索学术平台 → 模型逐篇介绍论文主题与研究要点，并附上页面链接与 PDF 下载地址。
- **实现状态**：✅ 已实现（`search_academic` 工具 + `gduf-academic-api` 客户端 + 学术资源适配层）。结果属于纯文本降级类型，前端只展示模型总结的文字，不渲染原始条目 JSON。架构采用可扩展注册表模式，新增平台只需在 `platforms/` 目录下创建模块文件，无需修改其他代码。

## 四、统一的接口契约（业务视角）

所有接口返回统一结构，前端据此统一处理成功/失败：

```json
成功：{"success": true,  "data": {...}, "message": null}
失败：{"success": false, "data": null, "message": "请先登录", "code": "AUTH_REQUIRED"}
```

业务错误码（对用户可见的失败原因分类）：

| 错误码 | 含义 | 典型触发 |
|---|---|---|
| `AUTH_REQUIRED` | 尚未登录 | 未登录就查个人数据 |
| `AUTH_CAPTCHA_INVALID` | 验证码错误/过期 | 验证码一次性，输错需刷新 |
| `AUTH_FAILED` | 学号或密码错误 | 登录失败 |
| `SESSION_EXPIRED` | 教务会话失效 | 长时间未操作，需重新登录 |
| `UPSTREAM_ERROR` | 教务系统请求失败 | 教务系统故障或超时 |
| `PARSE_ERROR` | 教务页面解析失败 | 教务系统页面改版 |
| `KNOWLEDGE_NOT_FOUND` | 知识库无检索结果 | 关键词未命中 |
| `MODEL_ERROR` | 模型服务失败/超时 | DeepSeek 接口异常 |
| `INVALID_PARAM` | 参数不合法 | 学期格式错误、index 不存在等 |

## 六、体验一遍核心功能的建议路径

1. 启动后端与前端（命令见《技术栈说明.md》5.2 节），浏览器打开 `http://localhost:5173`；
2. 未登录也能试知识问答、官网搜索、竞赛查询和学术资源搜索：在聊天页问“学院最近有什么通知”“最近有什么竞赛可以参加”或“帮我找几篇关于深度学习的论文”，观察模型总结的实时内容；
3. 用真实学号走一遍登录页的验证码流程；
4. 登录后依次试："我今天有什么课？""我这学期的成绩怎么样？"，观察结构化卡片；再追问"《XXX》这门课的明细"体验成绩明细的依赖顺序；
5. 试试连续提问体验多轮对话记忆（如先问"我有哪些课"，再追问"周三的课在哪个教室"）；
6. 打开各直达页面（课表/成绩/培养方案/教室课表/知识检索/资讯）核对与对话结果的一致性。

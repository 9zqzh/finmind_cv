# 学院教学小助手

## 前端页面技术选型与设计规范

> 版本：v1.0  
> 日期：2026-08-03  
> 适用阶段：本周 Web/H5 产品原型  
> 目标：指导前端团队在一周内完成可演示的登录、AI 对话和教务查询页面。  
> 关联文档：`学院教学小助手_综合需求文档.md`、`docs/技术选型与五人分工规划.md`

## 一、设计目标与范围

### 1.1 产品定位

学院教学小助手是面向学院本科生的一站式 AI 教学服务入口。前端以“自然语言对话 + 结构化查询卡片”为核心，同时提供课表、成绩、培养方案、教室课表和学院知识/资讯的直达页面。

### 1.2 本周前端目标

用户打开浏览器后，应能够完成以下闭环：

1. 输入学号、密码和验证码完成真实教务登录。
2. 在首页用自然语言询问“今天有什么课”“我这学期成绩如何”等问题。
3. 查看 Agent 返回的文本回答和结构化数据卡片。
4. 通过导航直接打开课表、成绩、培养方案、教室课表页面。
5. 搜索学院制度、学院信息和竞赛信息，并看到来源。
6. 在验证码错误、登录过期、查询为空或网络失败时获得清晰可操作的提示。

### 1.3 页面范围

| 页面 | 优先级 | 本周要求 |
|---|---:|---|
| 登录页 | P0 | 必须完成真实验证码登录 |
| AI 对话首页 | P0 | 必须完成快捷问题、流式或分段加载、结果卡片 |
| 课表页 | P0 | 必须完成日课表/周课表和课程详情 |
| 成绩页 | P0 | 必须完成成绩表、统计摘要和成绩明细 |
| 培养方案页 | P0 | 必须完成课程列表和学分统计 |
| 教室课表页 | P0 | 必须完成筛选和占用结果展示 |
| 知识/资讯页 | P1 | 尽量完成知识库、学院和竞赛搜索 |
| 设置/会话区域 | P1 | 至少完成退出登录和登录状态展示 |

### 1.4 本周不做

- 微信小程序专属页面和原生能力。
- 自动推送、浏览器通知和定时提醒配置。
- 完整管理员后台、内容审核和数据维护页面。
- 学习搭子、课程评价、社交互动和复杂用户画像。
- 生产级权限中心、复杂主题系统和多语言支持。

## 二、技术选型

### 2.1 推荐技术栈

| 层次 | 技术 | 选择理由 |
|---|---|---|
| 构建工具 | Vite | 启动快、配置少，适合本周原型 |
| UI 框架 | React | 组件化成熟，便于多人并行开发 |
| 开发语言 | TypeScript | 用类型约束接口数据，降低联调错误 |
| UI 组件库 | Ant Design | 表单、表格、卡片、通知、抽屉和响应式组件齐全 |
| 路由 | React Router | 支持登录路由、受保护页面和嵌套路由 |
| 请求层 | Axios | 统一处理 base URL、超时、错误和响应拦截 |
| 服务端状态 | TanStack Query | 管理查询缓存、加载、重试和失效刷新 |
| 本地状态 | React Context + `useReducer` | 仅管理认证信息、界面偏好和当前会话 |
| 表单 | Ant Design Form | 登录和筛选表单校验规则完善 |
| 图标 | Ant Design Icons | 与 UI 组件保持统一 |
| 图表 | ECharts 或轻量 CSS | 成绩趋势有需要时再引入，避免过度依赖 |
| 样式 | CSS Modules 或页面级 CSS | 防止样式污染，保证组件边界清晰 |
| 代码质量 | ESLint + Prettier | 统一格式和基础静态检查 |
| 测试 | Vitest + React Testing Library | 覆盖核心组件和用户交互 |

### 2.2 选择原则

- 优先使用团队已有生态和成熟组件，不为原型引入不必要的框架。
- 页面展示的数据结构必须与后端响应模型一致；不得在组件中重复解析后端原始 HTML。
- 查询类页面优先复用通用筛选栏、状态提示、空状态和结果卡片。
- 不把 API Key、教务密码、验证码或完整 Cookie 放进前端代码和浏览器持久化存储。
- 不将 Agent 的自然语言回答当作唯一数据源；课表、成绩等必须根据结构化字段渲染。

### 2.3 不建议本周采用

- Next.js、Nuxt 等需要额外服务端渲染设计的方案。
- Redux、MobX 等重状态方案，除非团队已有成熟模板。
- Tailwind、Ant Design、Element Plus 同时混用。
- 前端直接请求教务系统或大模型服务。
- 在浏览器中保存教务密码、DeepSeek Key 或完整会话 Cookie。

## 三、信息架构与路由

### 3.1 整体布局

登录后采用“**顶部品牌栏 + 左侧导航 + 主内容区**”的桌面布局；移动端将左侧导航收起为抽屉或底部导航。

```text
应用 Shell
├── 顶部栏
│   ├── 品牌名：学院教学小助手
│   ├── 当前登录状态
│   └── 用户菜单：账号信息 / 退出登录
├── 侧边导航
│   ├── AI 助手
│   ├── 我的课表
│   ├── 我的成绩
│   ├── 培养方案
│   ├── 教室课表
│   └── 知识与资讯
└── 主内容区
```

### 3.2 路由建议

| 路由 | 页面组件 | 是否需要登录 |
|---|---|---:|
| `/login` | `LoginPage` | 否 |
| `/` | `ChatPage` | 是 |
| `/schedule` | `SchedulePage` | 是 |
| `/grades` | `GradesPage` | 是 |
| `/training-plan` | `TrainingPlanPage` | 是 |
| `/classroom-schedule` | `ClassroomSchedulePage` | 是 |
| `/knowledge` | `KnowledgePage` | 否或按后端策略 |
| `/settings` | `SettingsPage` | 是 |
| `*` | `NotFoundPage` | 否 |

### 3.3 路由保护

- 未登录访问受保护路由时，跳转 `/login`，并携带 `redirect` 参数。
- 登录成功后返回用户原本要访问的页面；没有来源页面时进入 `/`。
- 后端返回 `AUTH_REQUIRED` 或 `SESSION_EXPIRED` 时，清理前端认证状态并跳转登录页。
- 登录页已登录时，默认跳转 `/`，避免重复登录。
- 不把敏感信息放进 URL 查询参数。

## 四、页面设计规范

### 4.1 登录页

### 页面目标

让用户完成真实教务系统验证码登录，并明确告知个人成绩和课表属于个人数据。

### 页面结构

```text
登录页
├── 品牌区域
│   ├── 学院教学小助手
│   └── 一站式 AI 教学服务
├── 登录卡片
│   ├── 学号输入框
│   ├── 密码输入框
│   ├── 验证码输入框 + 验证码图片
│   ├── 刷新验证码按钮
│   ├── 登录按钮
│   └── 登录错误提示
└── 安全提示
    └── 密码仅用于本次教务系统登录，不在浏览器保存
```

### 交互要求

- 页面加载时自动请求验证码；请求失败时显示刷新按钮。
- 验证码图片点击可刷新，刷新时保留学号但清空验证码输入。
- 学号、密码、验证码均为必填项；输入框按顺序支持 Tab 切换。
- 登录按钮提交后进入 loading 状态，禁止重复提交。
- 登录失败时展示后端返回的用户可理解提示，不展示堆栈信息。
- 验证码错误优先刷新验证码；账号密码错误不自动清空密码，避免用户重复输入。
- 登录成功后跳转目标页面或首页，并在页面顶部显示当前会话状态。
- 不提供“记住密码”选项。

### 表单规则

| 字段 | 规则 |
|---|---|
| 学号 | 必填，去除首尾空格；长度和格式交由后端最终校验 |
| 密码 | 必填，密码类型输入，不保存到 localStorage |
| 验证码 | 必填，去除首尾空格；建议限制合理长度 |

### 4.2 AI 对话首页

### 页面目标

提供最自然的入口，让用户通过一句话完成教务查询或知识问答；结果必须同时支持自然语言和结构化展示。

### 页面结构

```text
AI 助手页
├── 欢迎区
│   ├── 问候语
│   └── 当前登录账号/会话状态
├── 快捷问题区
│   ├── 今天有什么课？
│   ├── 查看本周课表
│   ├── 我这学期成绩如何？
│   ├── 培养方案还缺多少学分？
│   └── 缓考怎么申请？
├── 对话区
│   ├── 用户消息
│   ├── 助手文本消息
│   ├── 工具调用状态
│   └── 结构化结果卡片
└── 输入区
    ├── 多行输入框
    ├── 发送按钮
    └── 输入提示
```

### 对话交互

- Enter 发送，Shift+Enter 换行；移动端使用发送按钮。
- 发送后立即显示用户消息和助手 loading 状态。
- 工具调用过程可显示简短状态，例如“正在查询你的课表”。
- 失败时保留用户问题，并提供“重新发送”操作。
- 不因单次查询失败清空已有对话。
- 结果卡片提供“查看详情”“前往对应页面”等操作。
- 快捷问题点击后直接填入并发送，避免二次确认。
- 对话区域需要区分用户消息和助手消息，不能只依赖颜色区分。
- 知识库回答显示来源文件名或标题；没有可靠来源时显示依据不足提示。

### 消息数据建议

```ts
interface ChatMessage {
  id: string;
  role: 'user' | 'assistant' | 'system';
  content: string;
  createdAt: string;
  resultType?:
    | 'text'
    | 'schedule'
    | 'grades'
    | 'training_plan'
    | 'classroom_schedule'
    | 'knowledge';
  data?: unknown;
  sources?: SourceItem[];
  status?: 'sending' | 'success' | 'error';
}
```

### 结果卡片原则

- 先展示结论，再展示明细。
- 课表按日期/星期和节次组织，不把全部数据堆成一段文本。
- 成绩先展示学分、绩点等统计，再展示成绩表。
- 培养方案支持按课程属性筛选，并突出学分信息。
- 教室课表显示查询条件、空闲/占用结果和课程详情。
- 所有卡片都要有空数据状态和错误状态。

### 4.3 课表页

### 页面目标

让用户快速查看今天、本周或指定周次的个人课表，并能看懂课程时间、地点、教师和周次。

### 页面结构

```text
课表页
├── 页面标题 + 当前学期
├── 查询栏
│   ├── 学期选择
│   ├── 周次选择
│   ├── 今天按钮
│   └── 查询按钮
├── 日期/星期切换
├── 课表区域
│   ├── 桌面端：周视图网格
│   └── 移动端：按日期纵向课程列表
└── 课程详情抽屉/弹窗
```

### 课程卡片字段

- 课程名称
- 上课时间和节次
- 上课教室
- 任课教师
- 上课周次与单双周说明
- 课程备注（有则展示）
- 可选资料提醒（仅在后端提供依据时展示，不由前端自行编造）

### 交互要求

- 默认打开当前学期和当前周次；无法确定时提供明确选择器。
- 查询期间显示骨架屏或 loading，不显示旧数据造成误解。
- 无课程时显示“当前筛选条件下没有课程”，同时保留修改筛选条件的入口。
- 课程卡片点击打开详情，不跳转新页面。
- 桌面端课表网格最小可读宽度优先于强行压缩文字。
- 移动端不使用过窄的横向表格，优先纵向时间线或日期分组。

### 4.4 成绩页

### 页面目标

以清晰、克制的方式展示个人成绩和学情统计，避免将成绩分析做成带有评价压力的界面。

### 页面结构

```text
成绩页
├── 页面标题 + 学期筛选
├── 统计摘要卡
│   ├── 已修学分
│   ├── 剩余学分
│   ├── 专业 GPA
│   └── 辅修 GPA
├── 成绩表
│   ├── 课程名称
│   ├── 学期
│   ├── 成绩
│   ├── 学分
│   ├── 绩点
│   └── 查看明细
└── 成绩分析区
    └── 仅展示有真实数据依据的基础分析
```

### 交互要求

- 支持按学期、课程名称和课程属性筛选。
- 成绩明细使用抽屉或弹窗展示期末、期中、平时和总成绩。
- 没有明细链接时，隐藏或禁用“查看明细”按钮并给出原因。
- GPA 和学分缺失时显示“暂无数据”，不使用 0 代替。
- 分数、绩点等数据来自后端原始字段，前端不得自行推断等级。
- 成绩趋势图属于增强功能，只有在数据字段足够时显示；否则不展示空图表。

### 隐私规范

- 页面标题和卡片不展示完整敏感身份信息。
- 不支持通过前端修改学号查询他人成绩。
- 截图演示使用脱敏数据或用户本人授权数据。

### 4.5 培养方案页

### 页面目标

帮助学生理解培养方案课程、课程属性和学分完成情况，而不仅是展示一张原始表格。

### 页面结构

```text
培养方案页
├── 页面标题
├── 学分概览
│   ├── 已完成
│   ├── 计划要求
│   └── 待完成
├── 筛选栏
│   ├── 开课学期
│   ├── 课程属性
│   ├── 考核方式
│   └── 关键词
└── 课程列表/表格
```

### 交互要求

- 课程列表展示课程名称、课程代码、学期、开课单位、学分、学时、课程属性和是否考试。
- 移动端使用卡片列表；桌面端使用可横向滚动的表格。
- 筛选条件变更后应保留当前页面滚动位置，查询按钮状态清晰。
- 如果无法从接口判断已完成/待完成，前端只展示接口提供的课程数据，不自行标记。
- AI 对话中的培养方案结果可提供“打开培养方案页”操作。

### 4.6 教室课表页

### 页面目标

帮助用户查询指定校区、教学楼、周次和节次下的教室使用情况。

### 页面结构

```text
教室课表页
├── 页面标题
├── 筛选表单
│   ├── 学期
│   ├── 院系（如接口需要）
│   ├── 校区
│   ├── 教学楼
│   ├── 起止周
│   └── 起止节次
├── 查询结果摘要
└── 教室课程列表
```

### 交互要求

- 教学楼选项依赖校区选择；校区变化时清空无效教学楼。
- 查询按钮在必需条件满足后才可用。
- 结果中明确显示查询条件，避免用户误读旧结果。
- 空结果展示“当前条件下未查询到占用课程”，不能直接说“教室空闲”除非接口语义确认。
- 对长结果提供按日期、星期、教室或课程名称筛选。

### 页面目标

统一承载学院制度问答、学院基本信息、社团/工作室信息、学院网站信息和竞赛平台信息。

### 页面结构

```text
知识与资讯页
├── 搜索框
├── 分类 Tab
│   ├── 学院知识
│   ├── 制度流程
│   ├── 学院网站
│   └── 竞赛活动
├── 筛选/排序
├── 结果卡片
│   ├── 标题
│   ├── 摘要
│   ├── 分类标签
│   ├── 来源
│   └── 更新时间
└── 详情抽屉/弹窗
```

### 交互要求

- 搜索结果必须显示来源标题或来源文件名。
- 来源链接存在时提供“查看来源”；链接不存在时不要伪造链接。
- 长文本默认折叠摘要，用户点击后查看详情。
- 无结果时建议用户换关键词或转到 AI 对话继续提问。
- 对竞赛信息展示报名时间、面向对象、组织方和来源；字段缺失时显示“未提供”。
- 本周静态 JSON/Markdown 数据和后续正式爬虫数据使用同一前端字段结构。

## 五、通用组件规范

### 5.1 必备组件

建议在 `src/components/` 中建立以下可复用组件：

```text
components/
├── AppShell/                 # 顶部栏、侧边栏、响应式布局
├── AuthGuard/                # 路由保护
├── PageHeader/               # 标题、说明、操作区
├── QueryToolbar/             # 通用查询筛选栏
├── StatusMessage/             # 成功、警告、错误和信息提示
├── EmptyState/                # 空数据状态
├── LoadingState/              # 骨架屏和加载状态
├── SourceList/                # 知识库来源列表
├── ChatMessage/               # 对话消息
├── ChatInput/                 # 对话输入框
├── ScheduleCard/              # 课程卡片
├── GradeSummary/              # 成绩统计卡
├── GradeTable/                # 成绩表
├── TrainingPlanTable/         # 培养方案列表
└── ClassroomResultList/       # 教室课表结果
```

### 5.2 状态组件

所有查询页面必须处理四种状态：

1. **Loading**：请求进行中，保留页面布局，不让内容突然跳动。
2. **Success**：展示真实数据和更新时间/查询条件。
3. **Empty**：说明当前条件无数据，并给出修改筛选条件的建议。
4. **Error**：展示可理解原因和重试按钮；需要重新登录时提供登录入口。

### 5.3 按钮规范

- 一个页面的主操作按钮最多一个，使用主色。
- 查询、发送、登录等操作按钮在请求期间禁用。
- 删除、退出等可能影响状态的操作使用二次确认；退出登录可直接执行但需要明确反馈。
- “查看详情”“查看来源”等次要操作使用默认按钮或文字按钮。
- 禁用按钮需要保留可理解的原因，不只依赖灰色外观。

### 5.4 表格规范

- 桌面端允许横向滚动，移动端切换为卡片列表。
- 表头使用简洁中文名称；字段过长时通过 Tooltip 展示完整说明。
- 课程名称和竞赛标题优先展示，辅助字段次级展示。
- 不使用颜色单独表达成绩好坏或课程状态，必须配合文字、图标或标签。
- 空表格使用统一 `EmptyState`，不展示空白区域。

## 六、视觉设计规范

### 6.1 设计关键词

- 清晰：学生能够快速找到课表和成绩。

- 区块标题：18px，字重 600。
- 卡片标题：16px，字重 600。

- 辅助文本：12px-13px，颜色使用次要文本色。

- 基础间距单位：4px。

### 6.5 图标与插图

- 空状态可使用简洁线性插图，但必须同时提供文字说明和可操作按钮。
- 不使用与学校官方标识相似但未经授权的 Logo。

## 九、前后端接口对接规范

### 9.1 Axios 客户端

建议统一封装：

- `baseURL` 从 `VITE_API_BASE_URL` 读取。
- 默认超时 15-30 秒；大模型对话可单独设置更长超时。
- 请求失败统一转换为前端 `AppError`。
- 响应拦截器识别 `AUTH_REQUIRED` 和 `SESSION_EXPIRED`。
- 不在日志中输出请求体中的密码、验证码和敏感数据。

### 9.2 约定接口

| 方法 | 路径 | 前端用途 |
|---|---|---|
| `GET` | `/api/auth/captcha` | 获取验证码图片 |
| `POST` | `/api/auth/login` | 登录教务系统 |
| `POST` | `/api/auth/logout` | 退出当前会话 |
| `GET` | `/api/auth/status` | 恢复登录状态 |
| `POST` | `/api/chat` | 发送 AI 问题 |
| `GET` | `/api/schedule` | 获取个人课表 |
| `GET` | `/api/classroom-schedule` | 获取教室课表 |
| `GET` | `/api/grades` | 获取成绩列表和统计 |
| `GET` | `/api/grades/{index}/detail` | 获取成绩明细 |
| `GET` | `/api/training-plan` | 获取培养方案 |
| `GET` | `/api/knowledge/search` | 搜索知识库 |
| `GET` | `/api/information/search` | 搜索学院/竞赛资讯 |

### 9.3 统一响应处理

成功响应：

```ts
interface ApiResponse<T> {
  success: true;
  data: T;
  message: string | null;
  request_id?: string;
}
```

失败响应：

```ts
interface ApiErrorResponse {
  success: false;
  data: null;
  message: string;
  code: string;
  request_id?: string;
}
```

前端展示原则：

- `message` 是面向用户的提示，优先直接展示或转换为更友好的文案。
- `code` 用于决定交互，例如会话过期时跳转登录页。
- `request_id` 仅用于问题反馈，不主动展示给普通用户。
- 网络错误、超时和服务器错误分别给出不同提示。

### 9.4 对话响应

建议前端支持以下字段：

```ts
interface ChatResponse {
  answer: string;
  intent?: string;
  result_type?:
    | 'text'
    | 'schedule'
    | 'grades'
    | 'training_plan'
    | 'classroom_schedule'
    | 'knowledge';
  data?: unknown;
  sources?: SourceItem[];
  tool_calls?: ToolCallSummary[];
}
```

前端不要求暴露模型内部思考过程；工具调用状态只展示简短、可理解的进度信息。

## 十、状态管理与缓存策略

### 10.1 认证状态

认证状态至少包含：

```ts
interface AuthState {
  isAuthenticated: boolean;
  username?: string;
  sessionExpiresAt?: string;
  status: 'unknown' | 'authenticated' | 'unauthenticated';
}
```

- 页面刷新后通过 `/api/auth/status` 恢复状态。
- 不保存教务密码、验证码和 DeepSeek Key。
- 如果后端使用 HttpOnly Cookie，前端只保存非敏感的显示状态。
- 如果后端使用短期 token，前端优先使用内存保存；不要默认写入 localStorage。

### 10.2 查询缓存

- 课表、成绩和培养方案使用 TanStack Query 管理 loading、缓存和重试。
- 个人数据缓存时间不宜过长，建议原型阶段 1-5 分钟，并提供手动刷新。
- 登录退出时清理个人查询缓存。
- 查询参数作为缓存 key 的一部分，避免不同周次或学期数据混用。
- 失败响应不覆盖上一次成功数据，除非用户主动重试并确认查询条件变化。

### 10.3 本地历史

如实现最近查询，仅保存：

- 问题文本
- 查询时间
- 结果类型

不保存：

- 密码、验证码
- 完整成绩明细
- 教务 Cookie
- API Key
- 未脱敏个人身份信息

## 十一、文案与交互语气

### 11.1 文案原则

- 使用简洁、友好、明确的中文。
- 先说发生了什么，再说用户可以怎么做。
- 不使用“系统异常，请联系管理员”这类无行动指引的笼统提示。
- 不对成绩做价值判断，不使用“太差”“优秀学生”等标签。
- AI 回答不确定时，明确说明依据和信息更新时间。

### 11.2 推荐提示文案

| 场景 | 推荐文案 |
|---|---|
| 加载课表 | 正在查询你的课表… |
| 加载成绩 | 正在读取你的成绩信息… |
| 会话过期 | 教务登录已过期，请重新登录后继续查询。 |
| 验证码错误 | 验证码不正确，请刷新后重新输入。 |
| 查询无结果 | 当前筛选条件下没有找到数据，可以调整学期、周次或关键词后重试。 |
| 知识库无依据 | 当前知识库没有找到足够依据，我不建议直接下结论。你可以换个关键词或补充具体事项。 |
| 网络失败 | 网络请求未完成，请检查连接后重试。 |
| 模型失败 | AI 暂时无法完成这次回答，但你可以直接打开对应查询页面。 |
| 退出成功 | 已退出教务登录。 |

### 11.3 危险和敏感操作

- 退出登录：按钮文案明确为“退出登录”。
- 清空对话：如果实现，使用二次确认并说明仅清除本地对话。
- 成绩分析：在页面提示“分析仅供学习规划参考，不替代正式教务信息”。

|---|---|---|

### 12.3 Mock 与真实接口切换

- Service 层必须支持真实 API 和 Mock Adapter 两种实现。
- Mock 数据只用于界面开发和异常场景，不伪装成真实个人数据。
- 通过 `VITE_ENABLE_MOCK` 或开发环境配置切换，不在组件内写条件分支。
- Mock 响应字段必须与后端正式响应保持一致。
- 真实验证码登录链路优先联调；真实账号不可用时，使用 Mock 保证页面开发不阻塞。

## 十三、前端验收标准

### 13.1 功能验收

- 能在浏览器启动并访问登录页。
- 登录页能获取、刷新并展示验证码图片。
- 登录成功后能进入首页，登录失败有明确提示。
- 未登录访问业务页面会被拦截并跳转登录页。
- 首页能发送自然语言问题，并显示助手 loading、回答和结构化结果。
- 课表、成绩、培养方案、教室课表页面均能完成查询、加载、成功、空数据和失败状态。
- 成绩明细、课程详情和知识来源能够打开查看。
- 会话过期后能提示重新登录，不能静默显示旧数据。
- 退出登录后个人页面不可继续访问。

### 13.2 视觉验收

- 桌面端布局稳定，主内容区宽度合理，关键数据无需频繁横向滚动。
- 移动端页面可用，表单、卡片和按钮不重叠、不溢出。
- 主色、字体、间距、圆角和状态色符合本规范。
- Loading、Empty、Error 三类状态视觉统一。
- 对话消息、结构化卡片和来源信息层级清晰。
- 个人成绩页面克制、清晰，不使用过度强调或评价性视觉。

### 13.3 工程验收

- TypeScript 编译无错误。
- ESLint 和 Prettier 检查通过。
- 页面不直接请求教务系统或大模型服务。
- 不提交 `.env`、API Key、密码、验证码和完整 Cookie。
- Service、页面、组件和类型边界清晰。
- 至少为登录表单、认证路由和一个结果卡片编写基础测试。

## 十五、最终页面完成口径

本周前端完成的最低标准是：

> 用户打开浏览器，完成真实验证码登录，在 AI 对话页询问课表或成绩，看到自然语言回答和结构化结果卡片；同时可以通过导航打开课表、成绩、培养方案和教室课表页面，并在错误、空数据和会话过期时得到明确反馈。

## 三、真实教务登录联调步骤

1. 启动后端。
2. `POST /api/auth/captcha` → 拿到 `session_token` 和 base64 验证码图片（前端用 `<img src="data:image/jpeg;base64,...">` 渲染）。
3. `POST /api/auth/login` 提交 `session_token + 学号 + 密码 + 验证码`。
4. 后续所有请求带请求头 `X-Session-Token: <session_token>`。
5. `/api/chat` 也支持在 JSON body 里传 `session_token` 字段。

注意：
- 验证码与创建它的会话绑定，刷新验证码要重新调 `/api/auth/captcha`。
- 会话默认 120 分钟无活动过期（`SESSION_TTL_MINUTES` 可调）。
- 教务系统返回错误时，响应体 `code` 字段对应：`AUTH_CAPTCHA_INVALID` / `AUTH_FAILED` / `SESSION_EXPIRED` / `UPSTREAM_ERROR` / `PARSE_ERROR`。

## 四、如何新增一个 Agent 工具

以"查询教学楼列表"为例：

1. **适配层**：在 `app/adapters/jwxt.py` 增加 async 方法，内部用 `run_jwxt()` 包装同步调用，并做登录守卫。
2. **工具注册**：在 `app/agent/tools.py` 的 `register_tools()` 内仿照现有写法添加：

```python
@agent.tool
async def query_buildings(
    ctx: RunContext[AgentDeps],
    campus: Annotated[str, Field(description="校区代码")],
) -> dict[str, Any]:
    """查询某校区的教学楼列表。"""
    try:
        data = await jwxt_adapter.get_buildings(ctx.deps.session, campus)
    except ApiError as exc:
        return _record_failure(ctx, "query_buildings", exc.message)
    _record_success(ctx, "query_buildings", data)
    return data
```

3. **结果类型**：在 `RESULT_TYPES` 里登记工具名 → 前端卡片类型，并同步给前端。
4. **提示词**：在 `app/agent/prompts.py` 的能力清单里补一行说明。
5. **测试**：在 `tests/test_agent.py` 更新工具数量断言，必要时补充用例。

关键规则（踩坑记录）：
- 必填参数用 `Annotated[str, Field(description=...)]`，**不要**写成 `param: str = Field(...)`（默认值会被当成 FieldInfo 对象传入）。
- 工具内部业务错误返回 `{"error": ...}`（用 `_record_failure`），不要直接抛异常，让模型组织友好提示。
- 所有个人数据工具必须走适配层的登录守卫，严禁编造教务数据。

## 五、知识库资料导入

1. 把整理好的资料放入 `back_end/backend/data/knowledge/`（制度、手册、培养方案说明）或 `data/information/`（网站资讯、竞赛信息）。
2. 支持 `.md` / `.txt` / `.json`；Markdown 的 `#`/`##` 标题会作为来源标题展示。
3. JSON 格式建议为对象数组，含 `title` 字段，例如现有 `竞赛信息.json`。
4. 替换示例数据后**重启服务**即可生效（资料在启动时加载）。
5. 回答来源展示格式为 `文件名#标题`；检索不到时接口返回 404 + `KNOWLEDGE_NOT_FOUND`，Agent 会如实回答"没有找到依据"。

3. 用 `tests/test_knowledge.py` 回归验证召回效果。
4. 保留关键词检索作为兜底（embedding 服务不可用时自动降级）。

## 七、前后端联调要点

- 所有接口统一返回 `{success, data, message, code?}`。
- `/api/chat` 返回 `answer / intent / tool_calls / result_type / data / sources`；前端按 `result_type`（`schedule`、`grades`、`training_plan`、`classroom_schedule`、`knowledge`、`information`、`text`）渲染卡片。
- 联调前先冻结 schema：改动 `app/schemas/` 下任何模型，都要同步更新本文档与前端。
- 原型阶段 CORS 已放开（`*`），生产上线前必须在 `app/main.py` 收紧。

## 八、已知注意事项与踩坑记录

1. **密钥安全**：`.env.example` 中曾误放真实 DeepSeek Key（`sk-6279eafe...`），已清理为占位符。请到 DeepSeek 平台**撤销该 Key** 并重新生成，新 Key 只写本地 `.env`。若该仓库已推送过含 Key 的提交，还需清理 Git 历史。
2. **不要用 `asyncio.wait_for` 包裹 `agent.run()`**：会与 pydantic-ai 2.x 内部任务图冲突导致假性超时；超时控制依赖 OpenAI 客户端的 `timeout` 参数（已按 `AGENT_TIMEOUT_SECONDS` 配置）。
3. **模型名**：当前实测 `deepseek-v4-flash` 与 `deepseek-chat` 均可用；如账号模型列表不同，只改 `.env` 的 `DEEPSEEK_MODEL`。
4. **教务客户端是同步的**：适配层统一用 `asyncio.to_thread` 包装，新增教务调用时请沿用 `run_jwxt()`，不要在 async 路由里直接调同步方法。
5. **成绩明细依赖顺序**：`get_grade_detail` 要求同一会话先调用过 `get_grades`（客户端内部校验），Agent 的工具描述已说明该顺序。
6. **Agent 单例的系统提示词日期**在进程启动时生成；跨天运行时如需精确日期，可改为每次对话动态生成。

# 学院教学小助手

## 技术选型与五人分工规划

> 版本：v1.0  
> 规划日期：2026-08-03  
> 目标：在本周内完成可浏览器演示的 Web/H5 产品原型和基本功能闭环。  
> 当前状态：项目目录已有需求文档和 `gdufjwxtapi` 教务接口包，尚未建立 Web 应用主工程。

---

## 一、规划结论

本周采用“**Web/H5 + FastAPI + DeepSeek Tool Calling + 轻量 RAG + 真实教务接口**”的快速一体化方案。

本方案的核心原则：

1. 先完成可演示的端到端闭环，再完善扩展能力。
2. 教务查询优先走真实接口，知识库和学院信息采用可替换的数据文件。
3. Agent 只负责意图识别、参数提取、工具编排和自然语言组织；真实业务数据必须由工具返回。
4. 本周不引入复杂微服务、消息队列、正式部署和生产级运维设施。
5. 所有外部密钥使用环境变量，禁止写入代码、文档和 Git。

## 四、技术选型

### 4.1 前端

| 技术 | 选择 | 原因 |
|---|---|---|
| 框架 | React 18/19 + Vite | 启动快、组件生态成熟，适合一周原型 |
| 语言 | TypeScript | 统一接口类型，减少前后端联调错误 |
| UI | Ant Design | 表格、表单、Tag、Message、Modal 等后台/工具型组件齐全 |
| 路由 | React Router | 登录页、聊天页和查询页分离 |
| 请求 | `fetch` 或 Axios | 统一封装 token、错误提示和超时处理 |
| 状态 | React Context + 页面局部状态 | MVP 避免引入过重状态管理 |
| 图表 | ECharts 或轻量 CSS 展示 | 仅用于成绩趋势等基础可视化 |

前端页面建议：

- 登录页：验证码图片刷新、学号、密码、验证码输入。
- 首页/聊天页：对话区、快捷问题、输入框、会话状态。
- 课表页：日课表/周课表切换和课程卡片。
- 成绩页：学期筛选、成绩表、统计摘要、明细弹窗。
- 培养方案页：课程列表、课程属性、学分统计。
- 教室课表页：校区、教学楼、周次和节次筛选。
- 知识与资讯页：关键词搜索、来源标签、摘要卡片。

### 4.2 后端

| 技术 | 选择 | 原因 |
|---|---|---|
| Web 框架 | FastAPI | Python 生态适配教务包和 AI SDK，自动生成 OpenAPI 文档 |
| 数据校验 | Pydantic | 定义稳定的请求/响应模型 |
| HTTP 客户端 | 复用 `gdufjwxtapi` 内部 `httpx` 能力 | 减少重复封装 |
| 本地存储 | SQLite + SQLAlchemy/SQLModel | 原型足够，零配置，后续可迁移 PostgreSQL |
| 会话 | 服务端内存会话或 SQLite 会话表 | 绑定教务客户端实例；本周不做分布式会话 |
| 配置 | `.env` + Pydantic Settings | 隔离 API 地址、模型名和密钥 |
| 测试 | pytest + FastAPI TestClient | 覆盖工具适配、路由和异常场景 |

后端采用分层结构：

```text
backend/
  app/
    main.py                 # FastAPI 入口
    config.py               # 环境变量与配置
    schemas/                # 请求/响应模型
    api/                    # HTTP 路由
    services/               # 登录、查询、资讯、知识库服务
    adapters/
      jwxt.py               # gdufjwxtapi 适配层
    agent/
      model_client.py       # DeepSeek OpenAI 兼容客户端
      tools.py              # Agent 工具定义
      orchestrator.py       # 工具调用编排
    knowledge/               # 文档加载、切片、检索
    storage/                # SQLite 数据访问
```

### 4.3 Agent 与模型

- 接口格式：OpenAI 兼容 Chat Completions 或项目采用的官方兼容 SDK。
- 服务地址：通过环境变量配置，不在代码中硬编码。
- 模型名：按当前已确认的 `deepseek-v4-flash` 配置；若账号实际可用模型名不同，只修改环境变量。
- Agent 工具：`query_schedule`、`query_classroom_schedule`、`query_grades`、`query_grade_detail`、`query_training_plan`、`search_knowledge`、`search_information`。
- Agent 约束：涉及个人课表、成绩、培养方案时，必须先确认用户已登录；不能根据模型记忆编造教务数据；工具失败时返回可操作的错误提示。

推荐调用链：

```text
用户问题
  -> Agent 识别意图与参数
  -> 调用一个或多个后端 Tool
  -> Tool 访问教务接口/知识库
  -> 返回结构化 JSON
  -> DeepSeek 组织自然语言
  -> 前端按类型渲染文本或结果卡片
```

### 4.4 RAG 与信息查询

本周采用轻量实现，不引入 Milvus 等重型基础设施：

1. 资料统一放入 `data/knowledge/` 和 `data/information/`。
2. 支持 Markdown、TXT，PDF 可先转文本后导入。
3. 按标题、段落和固定长度切片，保留文件名、标题和更新时间元数据。
4. 优先使用本地向量检索库；若依赖安装或嵌入模型不可用，提供关键词检索兜底。
5. 回答强制附带来源名称，检索不到时明确回答“当前知识库没有找到依据”。
6. 学院网站和竞赛信息先用结构化 JSON/Markdown 静态数据，后续再接爬虫或平台 API。

候选实现选择：

- 首选：ChromaDB + 可用的中文 embedding 模型。
- 兜底：TF-IDF/关键词检索 + DeepSeek 摘要。
- 不建议本周使用：Milvus、复杂 LangGraph 流程、多服务向量数据库。

### 4.5 数据与安全

- 个人成绩和课表仅通过当前登录会话查询，不允许通过聊天参数传入他人学号查询。
- 教务客户端实例按用户会话隔离，禁止全局共享登录 Cookie。
- 密码和验证码只用于登录请求，不写入日志，不保存到浏览器 localStorage。
- API Key 使用 `DEEPSEEK_API_KEY` 环境变量，`.env` 加入 `.gitignore`。
- 日志只记录请求类型、耗时和错误类别，不记录成绩明细、密码、验证码和完整 Cookie。
- 教师信息只展示公开或已授权的办公信息，不展示私人手机号和微信号。
- 原型阶段仅做基本访问控制；生产环境还需补充 HTTPS、加密存储、审计和过期策略。

## 五、接口边界与统一约定

### 5.1 建议 HTTP 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/auth/captcha` | 获取验证码图片和会话标识 |
| `POST` | `/api/auth/login` | 使用学号、密码、验证码登录 |
| `POST` | `/api/auth/logout` | 退出当前会话 |
| `GET` | `/api/auth/status` | 查询登录状态 |
| `POST` | `/api/chat` | 发送问题，返回文本和可选结构化结果 |
| `GET` | `/api/schedule` | 查询个人课表 |
| `GET` | `/api/classroom-schedule` | 查询教室课表 |
| `GET` | `/api/grades` | 查询成绩列表和统计 |
| `GET` | `/api/grades/{index}/detail` | 查询单科成绩明细 |
| `GET` | `/api/training-plan` | 查询培养方案 |
| `GET` | `/api/knowledge/search` | 搜索知识库 |
| `GET` | `/api/information/search` | 搜索学院/竞赛资讯 |

### 5.2 统一响应结构

成功响应建议：

```json
{
  "success": true,
  "data": {},
  "message": null,
  "request_id": "可选"
}
```

失败响应建议：

```json
{
  "success": false,
  "data": null,
  "message": "请重新输入验证码",
  "code": "AUTH_CAPTCHA_INVALID",
  "request_id": "可选"
}
```

错误码至少包括：

- `AUTH_REQUIRED`：尚未登录。
- `AUTH_CAPTCHA_INVALID`：验证码错误或已过期。
- `AUTH_FAILED`：学号或密码错误。
- `SESSION_EXPIRED`：教务会话失效。
- `UPSTREAM_ERROR`：教务系统请求失败。
- `PARSE_ERROR`：教务页面解析失败。
- `KNOWLEDGE_NOT_FOUND`：知识库没有检索到可靠依据。
- `MODEL_ERROR`：模型服务请求失败。

### 5.3 前后端联调规则

- 先冻结 Pydantic 响应模型和一份 JSON 示例，再开始页面联调。
- 任何新增字段必须说明是否必填和默认值。
- 后端不返回 HTML 页面给前端，统一返回 JSON；验证码图片除外。
- Agent 返回 `answer`、`intent`、`tool_calls`、`result_type`、`data`、`sources` 等字段。
- 前端根据 `result_type` 渲染 `schedule`、`grades`、`training_plan`、`classroom_schedule`、`knowledge` 或 `text` 卡片。

## 八、验收标准

### 8.1 核心链路

- 能在浏览器打开 Web/H5 原型。
- 用户能获取验证码并使用真实学号、密码和验证码登录。
- 登录成功后能查询个人课表、成绩、培养方案和教室课表。
- 用户输入自然语言问题时，Agent 能正确选择至少五类工具中的对应工具。
- 工具结果以结构化卡片展示，并保留必要的来源或数据说明。
- 登录失效、验证码错误、查询为空和上游失败时，页面有明确提示。

### 8.2 知识库与资讯

- 至少导入一批学院制度/基本信息资料。
- 至少支持 10 个预设知识库问题。
- 回答能够展示来源文件名或来源标题。
- 检索不到时不编造答案，并给出补充提问建议。
- 学院网站和竞赛信息至少能通过静态数据搜索和摘要演示。

### 8.3 工程质量

- 前后端可分别启动，启动命令写入 README。
- `.env.example` 包含必要变量名但不含真实密钥。
- 教务适配层和核心 API 有基础测试。
- 不在日志和前端本地存储中保存密码、验证码、API Key 或完整 Cookie。
- 项目目录中不提交真实账号、真实成绩样本或敏感配置。

## 九、风险与兜底策略

| 风险 | 影响 | 兜底 |
|---|---|---|
| 验证码/真实账号当天不可用 | 无法演示真实查询 | 保留接口包的 MockTransport 测试数据，并提供演示数据模式；不影响 UI 和 Agent 演示 |
| DeepSeek 模型名或接口参数不兼容 | Agent 无法调用 | 使用 OpenAI 兼容客户端封装，模型名和地址全部可配置；保留固定意图路由兜底 |
| 教务系统页面结构变化 | 查询解析失败 | 显示明确上游错误；使用已验证样例数据完成非实时演示 |
| 中文 embedding 依赖安装失败 | RAG 不可用 | 自动切换关键词/TF-IDF 检索 |
| 五人并行产生接口冲突 | 联调延期 | D1 冻结接口契约；所有跨模块变更先更新示例 JSON |
| 需求继续膨胀 | 核心链路无法完成 | 以本文件 MVP 和验收标准为准，新增功能进入后续清单 |
| API Key 泄露 | 产生费用或安全风险 | 立即撤销已暴露密钥并重新生成；仅使用本地环境变量 |

## 十、运行配置建议

建议建立 `.env.example`，只保留变量名和非敏感默认值：

```env
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
JWXT_BASE_URL=https://jwxt.gduf.edu.cn
APP_ENV=development
SESSION_TTL_MINUTES=120
```

真实 `.env` 必须加入 `.gitignore`。由于 API Key 已在对话中公开，正式联调前应先在服务商后台撤销旧 Key，再生成新 Key 并写入本地环境变量。

## 十二、最终执行口径

本周只以以下结果作为成功标准：

> 用户打开浏览器，完成一次真实教务登录，用自然语言询问课表或成绩，系统调用真实工具返回结构化结果；用户还可以询问学院制度或竞赛信息，系统从知识库/资讯数据中检索并给出带来源的回答。

凡是不直接服务于上述闭环的工作，均不进入本周主线。

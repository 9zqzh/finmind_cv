## 一、项目整体目录树

```text
学院教学小助手/
├── .gitignore                        # 根级忽略规则（.env、.venv、node_modules 等）
├── .env.example                      # Docker 与本地开发统一配置模板
├── README.md                         # 项目总入口文档
├── compose.yaml                      # 前端、后端、PostgreSQL 与可选 Chroma 编排
├── resources/                        # 原始资料文件（PDF/docx，可通过 API 浏览与下载）
├── backend/                          # FastAPI + PydanticAI 主工程
├── frontend/                         # React + Vite + Nginx 工程
├── scripts/                          # 资源转换等维护脚本
└── docs/                             # 项目文档与前端设计规范
```

各部分一句话概括：**PyPI 包 `gduf-jwxt-api` 负责“从教务系统拿数据”，PyPI 包 `gduf-web-api` 负责“从学院官网拿数据”，固定提交的 Findpapers 依赖负责“从学术数据库拿数据”，`backend` 负责“编排与提供服务”，`frontend` 负责“把结果展示给用户”**。

### 知识库检索模块（2026-08-09）

```text
app/knowledge/
├── service.py        # 文档加载、切片、关键词检索和统一门面
├── embeddings.py     # 嵌入接口及 OpenAI 兼容嵌入服务适配器
├── chroma_store.py   # Chroma 持久化与相似度查询适配器
└── factory.py        # 根据配置创建知识库服务

data/chroma/          # 本地生成的 Chroma 向量索引（Git 忽略）
```

依赖方向固定为：API/Agent → `KnowledgeService` → 嵌入接口和 Chroma 适配器。API 层和 Agent 不直接依赖 Chroma，因此关键词与向量模式切换不会影响前端接口、文件去重或原始资料预览。

### 2.2 各模块职责与关键文件

#### `app/main.py` — 应用入口

- 通过 `lifespan` 在启动时初始化三样全局对象：`SessionManager`（会话管理器）、`knowledge` 与 `information` 两个 `KnowledgeService`（分别加载两个数据目录）。
- 挂载 5 个路由（auth/chat/jwxt/knowledge/resources）、CORS 中间件（原型阶段放开全部来源，生产需收紧）。
- 全局异常处理器：把业务异常 `ApiError` 和参数校验错误统一转成 `{success:false, code, message}` 格式。
- `GET /` 健康检查，返回服务名、环境、模型是否已配置。

#### `app/config.py` — 配置中心

`Settings` 类集中声明所有环境变量（DeepSeek 密钥/地址/模型、教务地址、会话时长、数据目录等），从 `.env` 自动加载；`get_settings()` 带缓存。详见《技术栈说明.md》第六节。

#### `app/api/` — 路由层（只做"接参数、调下层、包响应"）

| 文件 | 路由 | 职责 |
|---|---|---|
| `deps.py` | — | 依赖注入：请求级数据库会话、持久化登录会话与共享知识库 |
| `auth.py` | `/api/auth/*` | 验证码（创建会话+base64 图片）、登录、退出、登录状态 |
| `chat.py` | `POST /api/chat`、`POST /api/chat/stream` | Agent 对话入口：组装 `AgentDeps` → 调 `run_chat`（同步）或 `run_chat_stream`（SSE 流式） |
| `conversations.py` | `/api/conversations` | 对话历史列表、详情与删除 |
| `jwxt.py` | `/api/schedule` 等 5 个 GET + `/api/classroom-buildings` | 教务直达查询（课表/教室课表/成绩/成绩明细/培养方案/教学楼列表），均需登录 |
| `knowledge.py` | `/api/knowledge/search` | 统一知识库检索，无结果返回 404 `KNOWLEDGE_NOT_FOUND` |
| `information.py` | `/api/information/*` | 学院资讯获取与管理接口 |
| `competitions.py` | `/api/competitions/*` | 竞赛平台列表/通知/社团的 HTTP 直达接口 |
| `playbooks.py` | `/api/admin/playbooks/*` | 用户会话鉴权的操作手册列表、进化、草稿审核接口 |
| `resources.py` | `/api/knowledge/resources`、`/api/knowledge/resources/file` | 资料文件目录树浏览与下载/预览 |

#### `app/agent/` — Agent 层

| 文件 | 职责 |
|---|---|
| `model_client.py` | 构建 DeepSeek 模型对象：`AsyncOpenAI` 客户端 → `OpenAIProvider` → `OpenAIChatModel`；按 (base_url, model) 缓存实例；无密钥时抛 `RuntimeError` |
| `prompts.py` | 系统提示词模板：注入当前日期，约束模型"严禁编造教务数据、未登录先提示登录、检索无结果如实回答、地图结果必须附引用标签"等 |
| `tools.py` | **17 个工具的定义**与 `AgentDeps` 依赖容器；`RESULT_TYPES` 映射工具名→前端卡片类型；地图工具成功后登记 `citations`（引用卡片载荷）；成功/失败都记录到 deps 供编排层输出结构化结果 |
| `orchestrator.py` | Agent 单例构建、普通/流式对话、最近 4 轮持久化上下文；纯文本降级集合 `_TEXT_ONLY_RESULT_TYPES`；命中操作手册时把条目指令注入 `instructions` |
| `playbook.py` | 操作手册（Playbook）模块：加载 `data/playbooks/*.md`、关键词匹配（命中多者优先、平局取关键词总长度长）、热加载（按文件名+mtime 快照自动重载）、`save_entry` 落盘、命中统计 |
| `evolution.py` | 半自动进化流水线：高频提问聚类分析、模型总结草稿（含未知工具名校验警告）、草稿通过/拒绝 |
| `evolution_scheduler.py` | 定时自进化：按 `EVOLUTION_SCHEDULE_ENABLED`/`EVOLUTION_INTERVAL_DAYS` 周期触发进化流水线 |

17 个工具：`query_schedule`、`query_classroom_schedule`、`query_empty_classrooms`、`query_grades`、`query_grade_detail`、`query_training_plan`、`search_knowledge`、`search_information`、`search_website`、`get_website_detail`、`search_academic`、`query_competitions`、`query_competition_detail`、`query_competition_notices`、`query_competition_clubs`、`search_map_places`、`query_map_route`。

#### `app/adapters/jwxt.py` — 教务适配层

隔离 `gduf-jwxt-api` 与上层代码的"翻译官"，三个职责：

1. **异常映射**：`translate_jwxt_error()` 把 `CaptchaError`/`AuthenticationError`/`SessionExpiredError`/`ParseError`/`ValidationError`/`RequestError` 映射为带统一错误码的 `ApiError`；
2. **同步转异步**：`run_jwxt()` 用 `asyncio.to_thread` 包装同步客户端调用，避免阻塞事件循环；
3. **登录守卫**：`require_login()` 保证个人数据查询必须先登录。

业务方法（`get_captcha`/`login`/`get_schedule`/`get_grades`/`get_grade_detail`/`get_training_plan`/`get_classroom_schedule`/`get_empty_classrooms`/`get_buildings` 等）被**路由层和 Agent 工具共同复用**——这是"对话查询"与"页面直达查询"数据一致的关键。

#### `app/adapters/gduf_web.py` — 官网与竞赛平台适配层

隔离 `gduf-web-api` 与上层代码的“翻译官”，与教务适配层对齐的三段式架构：

1. **异常映射**：`translate_gduf_error()` 把 `InvalidPageError`/`ParseError`/`NetworkError` 等映射为带统一错误码的 `ApiError`；
2. **同步转异步**：`run_gduf()` 用 `asyncio.to_thread` 包装同步客户端调用；
3. **业务方法**：官网侧 `search_website()` 调用 `search_ai()` 搜索官网并整形结果（截断 `SEARCH_MAX_ITEMS=10` 条、只保留 title/url/published_at/summary）；竞赛平台侧 `get_competitions()`/`get_competition_detail()`/`get_competition_notices()`/`get_competition_clubs()` 分别包装 `get_aijspt_bslb`/`get_aijspt_bsxq`/`get_aijspt_tzgg`/`get_aijspt_stlb`，并整形裁剪（`COMPETITION_MAX_ITEMS=10` 条、摘要/正文截断 `SUMMARY_LIMIT=200` 字符）。

模块级 `GdufClient` 懒加载复用（官网与竞赛平台均无需登录，不同于教务的会话绑定客户端）。官网搜索（`search_website`）与竞赛平台四类查询（`query_competitions` 比赛列表/`query_competition_detail` 单场详情/`query_competition_notices` 平台通知/`query_competition_clubs` 竞赛社团）已注册为 Agent 工具；`run_gduf` 另将无效 ID/URL 的 `ValueError` 归一为 `INVALID_PARAM`。

#### `app/adapters/academic.py` — 学术资源适配层

隔离 Findpapers 与上层代码的“翻译官”，与教务/官网适配层对齐的三段式架构：

1. **异常映射**：`translate_findpapers_error()` 把查询、参数和连接器异常映射为带统一错误码的 `ApiError`；
2. **同步转异步**：`run_findpapers()` 用 `asyncio.to_thread` 包装同步客户端调用；
3. **业务方法**：`search_academic_resources()` 调用 `Engine.search()`，并把去重后的 `Paper` 结果整形为兼容结构（最多 8 条、摘要最多 200 字符）。

模块级 `Engine` 懒加载复用；并行搜索 `FINDPAPERS_DATABASES` 白名单中的数据库，关闭交互式进度条和额外 enrichment。默认启用 arXiv、PubMed 与 Semantic Scholar；代理、SSL、联系邮箱、数据库 Token、单请求/总超时和重试次数均使用 `FINDPAPERS_*` 环境变量配置。

#### `app/adapters/amap.py` — 高德地图适配层

- **业务方法**：`search_map_places()` 调用高德周边搜索（`/v3/place/around`，带 `extensions=all` 获取照片）或关键词搜索（`/v3/place/text`）；`query_map_route()` 调用路径规划（`/v3/direction/*`）并整形为统一结构。
- **数据整形**：POI 精简为名称/坐标/地址/电话/评分/人均/距离/城市/点评数/`image_url`（取高德返回的第一个 HTTPS 照片，无则空串）；仅保留 `https` 图片，过滤 `javascript:` 等危险 URL。
- **异常映射**：未配置 `AMAP_API_KEY`、配额耗尽、接口异常统一转为 `ApiError`，由工具层返回 `{"error": ...}` 让模型如实告知用户。
- **引用登记**：工具成功返回后，`tools.py` 的 `_register_map_citations()` 为每个地点/路线生成 `citation_ref` 并登记到 `deps.citations`，供前端渲染可点击地图卡片。

#### `app/services/` — 持久化登录与对话历史

- `session.py`：`SessionManager` 保存令牌摘要与加密 Cookie，并在缓存未命中时恢复独立 `JwxtClient`。
- `conversation.py`：`ConversationManager` 按用户校验、分页和删除 PostgreSQL 历史，并为 Agent 加载最近 4 轮。
- `crypto.py`：Fernet 会话加密工具，`SESSION_ENCRYPTION_KEYS` 支持多密钥轮换。

#### `app/knowledge/service.py` — 知识库检索

`KnowledgeService`：加载目录内 `.md/.txt/.json` → 切片（Markdown 按标题、超长段 400 字符再切、JSON 按记录）。配置完整嵌入服务时经 `chroma_store.py` 执行向量检索；未配置或异常时自动使用中文 bigram + 英数单词关键词检索。

#### `app/schemas/` — 契约层

| 文件 | 内容 |
|---|---|
| `common.py` | 9 个错误码常量（`AUTH_REQUIRED`、`SESSION_EXPIRED`、`MODEL_ERROR` 等）、`ApiError` 异常、`ok()/fail()` 响应包装 |
| `requests.py` | 请求模型：`LoginRequest`（学号/密码/验证码/session_token）、`ChatRequest`（message + 可选 session_token） |
| `chat.py` | `ChatResponse`（answer/intent/tool_calls/result_type/data/sources/citations/playbook）与 `ToolCallInfo`；`result_type` 是前端渲染卡片的依据；`citations` 是正文引用标签对应的可信结构化载荷（ref/type/title/url/data） |
| `conversation.py` | 对话历史分页、详情与删除的请求/响应模型 |

#### `data/` — 数据目录

- `knowledge/`：学院简介、缓考申请流程（**示例数据，待替换**为真实学生手册/制度文件）。
- `information/`：学院资讯.md、竞赛信息.json（**示例数据，待替换**；json 中每条记录一个对象，检索时按记录切片）。

- `playbook_drafts/`：自进化流水线生成的待审草稿（`source: draft`），不参与线上匹配。

## 三、教务客户端依赖 gduf-jwxt-api

后端唯一的教务数据来源是 PyPI 包 [`gduf-jwxt-api==0.2.0`](https://pypi.org/project/gduf-jwxt-api/)，Python 导入名为 `jwxtapi`。源码、解析器测试和完整 API 文档由[上游仓库](https://github.com/LiangJZ1/gduf-jwxt-api)独立维护；本仓库仅保留 `app/adapters/jwxt.py` 适配层。

**使用约束**：同步客户端；验证码与 `JSESSIONID` 绑定，获取验证码和登录必须用同一个实例；一个账号一个实例。这些约束决定了后端会话管理的设计。

---

## 三-B、官网与竞赛平台客户端依赖 gduf-web-api

后端学院官网与竞赛平台公开数据的唯一来源是 PyPI 包 [`gduf-web-api==0.2.1`](https://pypi.org/project/gduf-web-api/)，Python 导入名为 `gduf_web_api`。源码、页面 fixture、解析器测试和完整 API 文档由[上游仓库](https://github.com/LiangJZ1/gduf-web-api)独立维护；本仓库仅保留 `app/adapters/gduf_web.py` 适配层。

**使用约束**：同步客户端；无需登录；模块级 `GdufClient` 懒加载复用。内部按来源适配器协议组织：`SourceAdapter`（官网）与 `CompetitionSourceAdapter`（竞赛平台），新增来源不破坏既有 `get_ai_*`/`get_aijspt_*` 行为。

---

## 三-C、学术资源依赖 Findpapers

后端通过固定 GitHub 提交安装 [Findpapers](https://github.com/jonatasgrosman/findpapers)，本仓库只维护 `app/adapters/academic.py` 适配层。Findpapers 提供统一查询、跨库去重与 `Paper` 模型；默认白名单使用 arXiv、PubMed、Semantic Scholar，配置 Token 并加入白名单后可启用 OpenAlex、IEEE、Scopus 与 Web of Science。

**使用约束**：新版要求 Python 3.11+；`Engine.search()` 是同步调用，必须通过适配层在线程中执行。聊天工具只使用论文搜索能力，不启用批量下载、BibTeX、引用网络或相似论文功能。

```text
    │   └── AppLayout.tsx           # 主布局：侧边栏导航 + 用户信息 + 退出登录
    └── pages/
        ├── LoginPage.tsx           # 验证码刷新 + 学号/密码/验证码登录
        ├── ChatPage.tsx            # AI 对话：快捷问题 + 按 result_type 渲染结果卡片 + 地图引用卡片
        ├── citationParser.ts       # 解析 AI 正文中的 <citation> 标签，与后端 citations 对照生成卡片
        ├── SchedulePage.tsx        # 我的课表（学期/周次筛选 + 课程表格）
        ├── GradesPage.tsx          # 成绩查询（学期筛选 + 学分/绩点统计）
        ├── TrainingPlanPage.tsx    # 培养方案课程清单
        ├── ClassroomSchedulePage.tsx # 教室课表（学期/校区/教学楼筛选）
        ├── KnowledgePage.tsx       # 知识库搜索
        ├── InformationPage.tsx     # 资讯搜索
        └── AdminPage.tsx           # 操作手册管理台（待审草稿/手册列表/触发进化）
    └── utils/
        └── terms.ts                # 学期选项等前端常量
```

### 4.2 关键设计

- **路由表**（`App.tsx`）：`/login` 公开；`/`、`/schedule`、`/grades`、`/training-plan`、`/classroom-schedule`、`/knowledge` 受 `ProtectedLayout` 保护，未登录自动重定向到登录页；`/admin` 为操作手册管理台（不挂导航菜单，输入地址直达）。
- **请求层**（`api/client.ts`）：请求拦截器自动附带 `X-Session-Token`；响应拦截器统一拆包 `{success, data, message, code}`，业务失败抛 `ApiBizError`（带错误码），页面据此提示。
- **登录状态**（`context/AuthContext.tsx`）：token 存 `sessionStorage`；页面刷新时若有 token 则调 `/api/auth/status` 向后端确认登录是否仍有效。
- **版本号**（`layout/AppLayout.tsx`）：侧边栏底部展示 `package.json` 的 `version`（当前 v1.0.7）。
- **引用卡片**（`pages/citationParser.ts` + `ChatPage.tsx`）：把 AI 正文按 `<citation ref="cN">` 标签拆段，只有后端 `citations` 列表中真实存在的 ref 才渲染为地图卡片；卡片链接与图片只接受 https 且域名受限（`uri.amap.com`），未知引用降级为普通文字。

## 六、模块间调用链（重点）

### 6.1 一次 AI 提问的完整链路

以用户问"我这学期成绩怎么样"为例：

```text
① 前端 ChatPage
   POST /api/chat  {message, session_token}          ← axios 自动附带 token
        │（Vite 代理 /api → 127.0.0.1:8000）
        ▼
② 路由层 app/api/chat.py
   依赖注入：按 token 取 JwxtSession（可为空）、取两个 KnowledgeService
   调用 build_deps() 组装 AgentDeps
        ▼
③ 编排层 app/agent/orchestrator.py · run_chat()
   await agent.run(message, deps=deps)               ← PydanticAI 驱动
        ▼
④ DeepSeek 模型（OpenAI 兼容接口）
   模型理解意图 → 决定调用工具 query_grades(term="2025-2026-2")
        ▼
⑤ 工具层 app/agent/tools.py · query_grades
   try: 调用 jwxt_adapter.get_grades(session, term)
   except ApiError: 返回 {"error": ...} 让模型组织提示（如"请先登录"）
   成功则 _record_success：把 (result_type="grades", data) 记入 deps
        ▼
⑥ 适配层 app/adapters/jwxt.py
   require_login 守卫 → run_jwxt(asyncio.to_thread) → 同步 JwxtClient.get_grades()
   异常映射为 ApiError；结果 dataclass.to_dict() 转 dict
        ▼
⑦ 模型拿到真实数据 → 组织自然语言回答
        ▼
⑧ 编排层组装 ChatResponse
   {answer, intent, tool_calls, result_type:"grades", data, sources}
        ▼
⑨ 前端 ChatPage · ResultCard
   按 result_type 分支渲染：grades → 成绩表格卡片；
   schedule/training_plan/knowledge 等同理；无工具调用则只显示文本
```

**核心原则**：模型只负责"理解意图、选工具、组织语言"，**真实数据一律由工具返回**——所以不会出现模型编造课表或成绩的情况。

### 6.2 页面直达查询链路（绕过 Agent）

```text
前端页面（如 SchedulePage）
   GET /api/schedule?term=2025-2026-2   （请求头带 X-Session-Token）
        ▼
app/api/jwxt.py（依赖注入取会话，未登录抛 AUTH_REQUIRED 401）
        ▼
app/adapters/jwxt.py（与 Agent 工具复用同一套业务方法）
        ▼
jwxtapi.JwxtClient（线程包装）→ 结构化 dict 返回
```

两条链路共享适配层，保证"问 AI"和"点页面"看到的数据完全一致。

### 6.3 登录链路

```text
LoginPage 点"获取验证码"
   POST /api/auth/captcha
     → SessionManager.create() 新会话 + 新 JwxtClient
     → client.get_captcha() → base64 图片 + session_token 返回
前端保存 token（sessionStorage），展示验证码图
   POST /api/auth/login {session_token, username, password, captcha}
     → 同一会话的 client.login()（验证码与 JSESSIONID 绑定，必须同一实例）
     → 成功：前端 AuthContext.markLoggedIn → 跳转主页
```

### 6.4 result_type 与前端卡片对照表

| 工具 | result_type | 前端渲染 |
|---|---|---|
| query_schedule | `schedule` | 课表表格卡片 |
| query_classroom_schedule | `classroom_schedule` | 教室占用表格 |
| query_empty_classrooms | `empty_classrooms` | ⚠️ 纯文本降级，模型用自然语言汇总空闲教室名单 |
| query_grades | `grades` | 成绩表格 + 学分/绩点统计 |
| query_grade_detail | `grade_detail` | ⚠️ 前端暂无专属卡片，落入 JSON 兜底展示（待实现） |
| query_training_plan | `training_plan` | 培养方案表格 |
| search_knowledge / search_information | `knowledge` / `information` | ⚠️ 纯文本降级，模型基于检索片段作答 + 来源标签 |
| search_website | `website` | ⚠️ 纯文本降级，模型总结提炼官网搜索结果 |
| search_academic | `academic` | ⚠️ 纯文本降级，模型逐篇介绍论文并附上链接与 PDF 下载地址 |
| query_competitions | `competition` | ⚠️ 纯文本降级，模型逐场介绍比赛与报名状态并附链接 |
| query_competition_detail | `competition_detail` | ⚠️ 纯文本降级，模型介绍单场比赛详情要点并附链接 |
| query_competition_notices | `competition_notice` | ⚠️ 纯文本降级，模型归纳竞赛平台通知要点并附链接 |
| query_competition_clubs | `competition_club` | ⚠️ 纯文本降级，模型逐个介绍竞赛社团并附链接 |
| search_map_places | `map_places` | 地图地点卡片：正文引用标签原位渲染（评分/人均/点评/距离/地址/首图） |
| query_map_route | `map_route` | 地图路线卡片：正文引用标签原位渲染（出行方式/距离/耗时/导航按钮） |
| get_website_detail | `website_detail` | ⚠️ 纯文本降级，模型介绍文章/通知详情 |
| （无工具调用） | `text` | 纯文本回答 |

映射定义在后端 `app/agent/tools.py` 的 `RESULT_TYPES`，前端对应实现在 `ChatPage.tsx` 的 `ResultCard` 组件——新增工具时两处需要同步维护。注：标记为"纯文本降级"的类型，编排层会把 `result_type` 规范化为 `text`、`data` 置空，前端只展示模型总结的文字，不渲染原始 JSON。`ResultCard` 对未识别的 `result_type` 会回退为 JSON 格式化展示（`grade_detail` 目前即走此兜底）。

### 2.2 各模块职责与关键文件

#### `app/main.py` — 应用入口

- 通过 `lifespan` 在启动时初始化三样全局对象：`SessionManager`（会话管理器）、`knowledge` 与 `information` 两个 `KnowledgeService`（分别加载两个数据目录）。
- 挂载 5 个路由（auth/chat/jwxt/knowledge/resources）、CORS 中间件（原型阶段放开全部来源，生产需收紧）。
- 全局异常处理器：把业务异常 `ApiError` 和参数校验错误统一转成 `{success:false, code, message}` 格式。
- `GET /` 健康检查，返回服务名、环境、模型是否已配置。

#### `app/config.py` — 配置中心

`Settings` 类集中声明所有环境变量（DeepSeek 密钥/地址/模型、教务地址、会话时长、数据目录等），从 `.env` 自动加载；`get_settings()` 带缓存。详见《技术栈说明.md》第六节。

#### `app/api/` — 路由层（只做"接参数、调下层、包响应"）

| 文件 | 路由 | 职责 |
|---|---|---|
| `deps.py` | — | 依赖注入：从请求头 `X-Session-Token` 解析会话、从 `app.state` 取知识库 |
| `auth.py` | `/api/auth/*` | 验证码（创建会话+base64 图片）、登录、退出、登录状态 |
| `chat.py` | `POST /api/chat`、`POST /api/chat/stream` | Agent 对话入口：组装 `AgentDeps` → 调 `run_chat`（同步）或 `run_chat_stream`（SSE 流式） |
| `jwxt.py` | `/api/schedule` 等 5 个 GET + `/api/classroom-buildings` | 教务直达查询（课表/教室课表/成绩/成绩明细/培养方案/教学楼列表），均需登录 |
| `knowledge.py` | `/api/knowledge/search`、`/api/information/search` | 关键词检索，无结果返回 404 `KNOWLEDGE_NOT_FOUND` |
| `resources.py` | `/api/knowledge/resources`、`/api/knowledge/resources/file` | 资料文件目录树浏览与下载/预览 |

#### `app/agent/` — Agent 层

| 文件 | 职责 |
|---|---|
| `model_client.py` | 构建 DeepSeek 模型对象：`AsyncOpenAI` 客户端 → `OpenAIProvider` → `OpenAIChatModel`；按 (base_url, model) 缓存实例；无密钥时抛 `RuntimeError` |
| `prompts.py` | 系统提示词模板：注入当前日期，约束模型"严禁编造教务数据、未登录先提示登录、检索无结果如实回答"等 |
| `tools.py` | **10 个工具的定义**与 `AgentDeps` 依赖容器；`RESULT_TYPES` 映射工具名→前端卡片类型；成功/失败都记录到 deps 供编排层输出结构化结果 |
| `orchestrator.py` | Agent 单例构建（模型+工具+提示词）、`run_chat()`（同步对话）、`run_chat_stream()`（SSE 流式对话）、多轮记忆管理（滑动窗口 6 轮）；纯文本降级集合 `_TEXT_ONLY_RESULT_TYPES` |

10 个工具：`query_schedule`、`query_classroom_schedule`、`query_empty_classrooms`、`query_grades`、`query_grade_detail`、`query_training_plan`、`search_knowledge`、`search_information`、`search_website`、`search_academic`。

#### `app/adapters/jwxt.py` — 教务适配层

隔离 `gduf-jwxt-api` 与上层代码的"翻译官"，三个职责：

1. **异常映射**：`translate_jwxt_error()` 把 `CaptchaError`/`AuthenticationError`/`SessionExpiredError`/`ParseError`/`ValidationError`/`RequestError` 映射为带统一错误码的 `ApiError`；
2. **同步转异步**：`run_jwxt()` 用 `asyncio.to_thread` 包装同步客户端调用，避免阻塞事件循环；
3. **登录守卫**：`require_login()` 保证个人数据查询必须先登录。

业务方法（`get_captcha`/`login`/`get_schedule`/`get_grades`/`get_grade_detail`/`get_training_plan`/`get_classroom_schedule`/`get_empty_classrooms`/`get_buildings` 等）被**路由层和 Agent 工具共同复用**——这是"对话查询"与"页面直达查询"数据一致的关键。

#### `app/adapters/gduf_web.py` — 官网适配层

隔离 `gduf-web-api` 与上层代码的"翻译官"，与教务适配层对齐的三段式架构：

1. **异常映射**：`translate_gduf_error()` 把 `InvalidPageError`/`ParseError`/`NetworkError` 等映射为带统一错误码的 `ApiError`；
2. **同步转异步**：`run_gduf()` 用 `asyncio.to_thread` 包装同步客户端调用；
3. **业务方法**：`search_website()` 调用 `search_ai()` 搜索官网并整形结果（截断 `SEARCH_MAX_ITEMS=10` 条、只保留 title/url/published_at/summary）。

模块级 `GdufClient` 懒加载复用（官网无需登录，不同于教务的会话绑定客户端）。

#### `app/adapters/academic.py` — 学术资源适配层

隔离 `gduf-academic-api` 与上层代码的“翻译官”，与教务/官网适配层对齐的三段式架构：

1. **异常映射**：`translate_academic_error()` 把 `ValidationError`/`ParseError`/`NetworkError` 等映射为带统一错误码的 `ApiError`；
2. **同步转异步**：`run_academic()` 用 `asyncio.to_thread` 包装同步客户端调用；
3. **业务方法**：`search_academic_resources()` 调用 `AcademicClient.search()` 并整形结果（截断 `SEARCH_MAX_ITEMS=8` 条、摘要截断 `ABSTRACT_LIMIT=200` 字符、作者最多 `MAX_AUTHORS=5` 人）。

模块级 `AcademicClient` 懒加载复用（学术平台无需登录）。支持 `ACADEMIC_PROXY` 环境变量配置代理。

#### `app/services/session.py` — 会话管理

- `JwxtSession`：一次用户会话，绑定独立 `JwxtClient`、记录学号、缓存最近一次成绩列表（`last_grade_report`，供"按 index 查成绩明细"）、对话记忆（`chat_history: list[ChatTurn]`，滑动窗口 6 轮）。
- `SessionManager`：内存字典 `token → 会话`，线程锁保护，TTL（默认 120 分钟）空闲过期自动清理。

#### `app/knowledge/service.py` — 知识库检索

`KnowledgeService`：加载目录内 `.md/.txt/.json` → 切片（Markdown 按标题、超长段 400 字符再切、JSON 按记录）→ 中文 bigram + 英数单词评分检索。零第三方依赖。

#### `app/schemas/` — 契约层

| 文件 | 内容 |
|---|---|
| `common.py` | 9 个错误码常量（`AUTH_REQUIRED`、`SESSION_EXPIRED`、`MODEL_ERROR` 等）、`ApiError` 异常、`ok()/fail()` 响应包装 |
| `requests.py` | 请求模型：`LoginRequest`（学号/密码/验证码/session_token）、`ChatRequest`（message + 可选 session_token） |
| `chat.py` | `ChatResponse`（answer/intent/tool_calls/result_type/data/sources）与 `ToolCallInfo`；`result_type` 是前端渲染卡片的依据 |

#### `data/` — 数据目录

- `knowledge/`：学院简介、缓考申请流程（**示例数据，待替换**为真实学生手册/制度文件）。
- `information/`：学院资讯.md、竞赛信息.json（**示例数据，待替换**；json 中每条记录一个对象，检索时按记录切片）。

#### `tests/` — 测试

- `test_knowledge.py`（5 个）：切片加载、中文命中、JSON 记录、未命中、目录缺失。
- `test_api.py`（7 个）：TestClient 测健康检查、未登录 401、无效 token、检索命中与 404。
- `test_agent.py`（4 个）：10 工具注册、`TestModel` 免网络运行、登录守卫、依赖构建。
- `test_gduf_web_adapter.py`（6 个）：官网适配层字段保留、截断、空结果提示、错误码映射、参数转发、网络异常转换。
- `test_academic_adapter.py`（7 个）：学术资源适配层字段保留、截断、错误码映射、参数透传、异常转换。
- `test_empty_classrooms.py`（3 个）：空闲教室过滤逻辑、边界情况。
- `test_text_only_downgrade.py`（3 个）：纯文本降级（empty_classrooms/website/knowledge/information 不泄漏结构化数据到前端）。
- `test_memory.py`（6 个）：对话记忆存储与恢复、滑动窗口裁剪、序列化容错。

### 4.2 关键设计

- **路由表**（`App.tsx`）：`/login` 公开；`/`、`/schedule`、`/grades`、`/training-plan`、`/classroom-schedule`、`/knowledge` 受 `ProtectedLayout` 保护，未登录自动重定向到登录页。
- **请求层**（`api/client.ts`）：请求拦截器自动附带 `X-Session-Token`；响应拦截器统一拆包 `{success, data, message, code}`，业务失败抛 `ApiBizError`（带错误码），页面据此提示。
- **登录状态**（`context/AuthContext.tsx`）：token 存 `sessionStorage`；页面刷新时若有 token 则调 `/api/auth/status` 向后端确认登录是否仍有效。

## 六、模块间调用链（重点）

### 6.1 一次 AI 提问的完整链路

以用户问"我这学期成绩怎么样"为例：

```text
① 前端 ChatPage
   POST /api/chat  {message, session_token}          ← axios 自动附带 token
        │（Vite 代理 /api → 127.0.0.1:8000）
        ▼
② 路由层 app/api/chat.py
   依赖注入：按 token 取 JwxtSession（可为空）、取两个 KnowledgeService
   调用 build_deps() 组装 AgentDeps
        ▼
③ 编排层 app/agent/orchestrator.py · run_chat()
   await agent.run(message, deps=deps)               ← PydanticAI 驱动
        ▼
④ DeepSeek 模型（OpenAI 兼容接口）
   模型理解意图 → 决定调用工具 query_grades(term="2025-2026-2")
        ▼
⑤ 工具层 app/agent/tools.py · query_grades
   try: 调用 jwxt_adapter.get_grades(session, term)
   except ApiError: 返回 {"error": ...} 让模型组织提示（如"请先登录"）
   成功则 _record_success：把 (result_type="grades", data) 记入 deps
        ▼
⑥ 适配层 app/adapters/jwxt.py
   require_login 守卫 → run_jwxt(asyncio.to_thread) → 同步 JwxtClient.get_grades()
   异常映射为 ApiError；结果 dataclass.to_dict() 转 dict
        ▼
⑦ 模型拿到真实数据 → 组织自然语言回答
        ▼
⑧ 编排层组装 ChatResponse
   {answer, intent, tool_calls, result_type:"grades", data, sources}
        ▼
⑨ 前端 ChatPage · ResultCard
   按 result_type 分支渲染：grades → 成绩表格卡片；
   schedule/training_plan/knowledge 等同理；无工具调用则只显示文本
```

**核心原则**：模型只负责"理解意图、选工具、组织语言"，**真实数据一律由工具返回**——所以不会出现模型编造课表或成绩的情况。

### 6.2 页面直达查询链路（绕过 Agent）

```text
前端页面（如 SchedulePage）
   GET /api/schedule?term=2025-2026-2   （请求头带 X-Session-Token）
        ▼
app/api/jwxt.py（依赖注入取会话，未登录抛 AUTH_REQUIRED 401）
        ▼
app/adapters/jwxt.py（与 Agent 工具复用同一套业务方法）
        ▼
gdufjwxtapi JwxtClient（线程包装）→ 结构化 dict 返回
```

两条链路共享适配层，保证"问 AI"和"点页面"看到的数据完全一致。

### 6.3 登录链路

```text
LoginPage 点"获取验证码"
   POST /api/auth/captcha
     → SessionManager.create() 新会话 + 新 JwxtClient
     → client.get_captcha() → base64 图片 + session_token 返回
前端保存 token（sessionStorage），展示验证码图
   POST /api/auth/login {session_token, username, password, captcha}
     → 同一会话的 client.login()（验证码与 JSESSIONID 绑定，必须同一实例）
     → 成功：前端 AuthContext.markLoggedIn → 跳转主页
```

### 6.4 result_type 与前端卡片对照表

| 工具 | result_type | 前端渲染 |
|---|---|---|
| query_schedule | `schedule` | 课表表格卡片 |
| query_classroom_schedule | `classroom_schedule` | 教室占用表格 |
| query_empty_classrooms | `empty_classrooms` | ⚠️ 纯文本降级，模型用自然语言汇总空闲教室名单 |
| query_grades | `grades` | 成绩表格 + 学分/绩点统计 |
| query_grade_detail | `grade_detail` | ⚠️ 前端暂无专属卡片，落入 JSON 兜底展示（待实现） |
| query_training_plan | `training_plan` | 培养方案表格 |
| search_knowledge / search_information | `knowledge` / `information` | ⚠️ 纯文本降级，模型基于检索片段作答 + 来源标签 |
| search_website | `website` | ⚠️ 纯文本降级，模型总结提炼官网搜索结果 |
| search_academic | `academic` | ⚠️ 纯文本降级，模型逐篇介绍论文并附上链接与 PDF 下载地址 |
| （无工具调用） | `text` | 纯文本回答 |

映射定义在后端 `app/agent/tools.py` 的 `RESULT_TYPES`，前端对应实现在 `ChatPage.tsx` 的 `ResultCard` 组件——新增工具时两处需要同步维护。注：标记为"纯文本降级"的类型，编排层会把 `result_type` 规范化为 `text`、`data` 置空，前端只展示模型总结的文字，不渲染原始 JSON。`ResultCard` 对未识别的 `result_type` 会回退为 JSON 格式化展示（`grade_detail` 目前即走此兜底）。
